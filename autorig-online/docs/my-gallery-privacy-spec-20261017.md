# «Мои модели»: личная галерея с управлением на карточке — приватность и полное удаление (ТЗ, 2026-10-17)

Владелец, 2026-10-17, на обращение подписчицы (support 48307, задача b7ae6208 «Singapore Sentinel»):
«сделай личную галерею с быстрым управлением прям по карточке галереи». Пользователь: «please allow me to make the
models private and have the ability to fully remove them … I see my model still publicly available and even on
telegram as previews».

**Почему это срочно.** Тариф продаёт это прямо сейчас (`buy_plan_feature_private` «Private models»,
`buy_credits_section_intro` «private models, and gallery visibility controls»), а в коде ни один путь не ставит
`tasks.is_public = false`: колонка есть (default TRUE), её уважают галерея, SEO и вьювер, но переключить её нельзя.
Подписчик заплатил за функцию, которой нет.

## 1. Что сделал бы ведущий специалист (а в запросе этого нет)

* Начал бы не с UI, а с **карты утечек**: каждый путь, по которому модель задачи видна постороннему. Кнопка
  «приватно», которая прячет карточку из галереи, но оставляет `/u/<id>/model.glb`, OG-картинку, превью в Telegram,
  ролик на YouTube и ссылку «топ-5 похожих», — это обман, а не приватность.
* Развёл бы два действия: **приватность** (обратима, мгновенна) и **удаление** (стирание везде, с окном отмены
  и журналом), и проверял бы каждое по той же карте.
* Проверил бы **авторизацию** как атакующий: чужой пользователь, аноним, владелец-аноним по cookie, админ;
  IDOR по id задачи, CSRF, гонки двойного клика, массовые операции.
* Решил бы **значения по умолчанию** по тому, что продано: у активного подписчика новые модели приватны
  (настройка в кабинете, по умолчанию вкл.); при оформлении подписки — одно предложение «сделать приватными все мои модели».
* Учёл бы **внешние копии**, которые мы не контролируем мгновенно: кэши поисковиков (noindex + 404/410 + удаление
  из sitemap), браузерные/nginx-кэши, сообщения Telegram, YouTube.

## 2. Первичные данные (вместо пересказа)

* Схема и данные БД: `/srv/autorig/data/db/autorig.db` (sqlite) — `tasks` (owner_type, owner_id, is_public,
  input_url, viewer_settings.v3.session.mt_run_id), `users.autorig_subscription_status`, `telegram_notifications`
  (event_type task_new/task_done, message_id, deleted_at), таблицы YouTube-аплоадов, коллекций, похожих.
* Конфиг nginx `/etc/nginx/sites-enabled/autorig.online-storage`: какие пути отдаются **мимо бэкенда**
  (alias на `/srv/autorig/data/static/tasks`, `glb_cache`, `/u/…`, видео, постеры, MT runs). Всё, что мимо бэкенда,
  не защищено `is_public` — это главный риск.
* Код: все чтения `is_public` (`grep -n is_public backend/*.py`: main.py 8811/14774, seo_gallery.py 300,
  seo_social.py 131/289/804/876/895, task_downloads_v3.py 613, task_page_v3_routes.py 517, v3_runtime_mount.py 393,
  v3_textures.py 584, v3_viewer_routes.py 341–450) и **все места, которые его не читают**, но отдают модель:
  `/api/gallery`, sitemap, `/api/mt/similar` и строки «топ-5 похожих» в уведомлениях (`telegram_task_completion.py`),
  OG/social, MT `/api/mt/runs/<run>/…` (файлы рана), YouTube-аплоадер, Astra/агенты, корпус автотестов.
* Удаление уже есть у админа: `admin_delete_task_full` (main.py ~13107: `_delete_task_artifacts` +
  `_delete_task_record_and_related`). Прочитать, что именно оно стирает, и сравнить с картой.
* access-логи nginx за неделю по id реальной задачи — какие URL этой модели реально запрашиваются снаружи.
* Живая задача-канарейка своего тестового аккаунта, а не клиентская.

## 3. Методы и инструменты

* **Матрица экспозиции** `tools/privacy_exposure.py <task_id>`: перечисляет все URL и файлы задачи (страница, API,
  GLB/FBX/ZIP/превью/видео/постер, `/u/` исходник, MT run, OG, sitemap-строка, галерея, похожие, сообщения Telegram,
  YouTube) и для каждого — ожидаемый ответ для аноним / чужой / владелец / админ в состояниях public / private / deleted.
  Прогон делает реальные запросы **снаружи VPS** (с ПК владельца) и пишет таблицу ожидалось/получено.
* **Бэкенд:** `PATCH /api/my/tasks/{id}` `{is_public}` и `DELETE /api/my/tasks/{id}` (+ bulk `POST /api/my/tasks/bulk`
  `{ids, action: private|public|delete}`), только владелец (user по email или anon по своему cookie) или админ;
  `GET /api/my/tasks` — список с полями карточки и `is_public`, пагинация. Приватность в каждом пути карты:
  файлы мимо бэкенда закрыть (nginx `auth_request` на маленький эндпоинт проверки доступа, или выдача приватных
  файлов только через бэкенд / подписанные короткие URL). OG/social у приватной — нейтральная карточка без медиа;
  `X-Robots-Tag: noindex`, выпадение из sitemap и галерей, из «похожих» для других.
* **Удаление:** мгновенно скрыть (как private) + отметка `deleted_requested_at`; тост «Отменить» 10 с на карточке;
  затем стирание через общий с админом путь, дополненный тем, чего в нём нет по карте: MT run, кэши, Telegram
  (`deleteMessage` по `telegram_notifications.message_id` во всех чатах; где message_id нет — записать в отчёт
  лиду, что удалить вручную), YouTube (снять/удалить ролик, если был), строки похожих/эмбеддингов.
  Журнал `privacy_audit` (кто, когда, что стёрто, что не удалось) — без содержимого модели.
  Это прямое исключение из «исходники клиентов не удаляются»: удаление по запросу владельца модели.
* **Значения по умолчанию:** активный подписчик → новые задачи `is_public=false` (настройка в `/dashboard`,
  по умолчанию вкл.); бесплатный — публично, переключатель «приватно» показан с замком и ссылкой на тариф;
  **удаление своих моделей доступно всем**, не только подписчикам. Приватная задача не уходит в публичные
  Telegram-уведомления с медиа и не загружается на YouTube.
* **UI** (иконки + тултипы, без абзацев — правило владельца): страница «Мои модели» (`/my` или раздел `/dashboard`)
  на тех же карточках, что галерея (`static/js/task-card.js`); на карточке: 🔒/🌐 переключатель, 🗑 удалить, ✓ выбор
  для массовых действий; оптимистичное обновление с откатом при ошибке; клавиатура и фокус; i18n en/ru/zh/hi/fa
  (fa — RTL) через `tools/i18n_merge.py`; та же кнопка 🔒/🗑 на странице задачи у владельца; ссылка «Мои модели»
  в шапке/меню аккаунта (серверный HTML, SEO-правило).
* Тесты бэкенда (`backend/tests/test_my_tasks_privacy.py`): владелец/чужой/аноним/админ, IDOR, bulk, отмена удаления,
  подписчик-по-умолчанию; случай добавить в релизный гейт.

## 4. Независимые доказательства

* Матрица экспозиции **снаружи VPS** на канарейке: public → всё 200; private → аноним и чужой получают 404/403 на
  каждом URL, включая прямые файлы, OG без медиа, нет в `/api/gallery`, sitemap, «похожих»; владелец и админ — 200.
  deleted → 404/410 везде, `find` по id/sha задачи на диске пусто, строки БД нет (кроме аудита), сообщения Telegram
  удалены (Bot API отвечает, что сообщения нет).
* Вторая учётная запись / приватное окно в реальном браузере не видит и не скачивает.
* access-лог nginx: запросы к файлам приватной/удалённой задачи после переключения — 403/404.
* Гейт бэкенда PASS, новые тесты зелёные.
* Итог — подписчица сама делает свою модель приватной/удаляет её в интерфейсе (лид пишет ей в саппорт, когда готово).

## Порядок и ограничения

1. Карта утечек + матрица (числа до кода). 2. Бэкенд приватности + закрытие файловых путей. 3. UI карточек и `/my`.
4. Удаление с отменой и Telegram/YouTube. 5. Подписчик-по-умолчанию + bulk «всё приватно».
Сначала выкатывается приватность (1–3) — это то, что продано; удаление — следом.
Деплой: бэкенд — staged release + `gate backend` PASS, статик — `live_static.py put`; Git main через чистый worktree
(без `reset --hard`); перед правкой общего файла перечитать прод-копию. Клиентские задачи не трогать, кроме канарейки
своего тестового аккаунта; задачу b7ae6208 не менять — её владелица сделает это сама. В DEV не писать: отчёт лиду
(таблица матрицы до/после, коммиты, релизы).
