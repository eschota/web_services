База эмбеддингов AutoRig V3

Что реализовано, как работает, где используется и где нет. Снято с кода прода 2026-10-14 (file:line в отчёте картографа; здесь только суть).

Коротко

Настоящих векторных баз три: индекс скелетов, кэш анализа и библиотека текстур. Всё остальное, что ведёт себя как «база категории», — рукописные таблицы правил, списки слов и папки клипов по видам. Ни одна из баз не участвует в выборе оси «верх», плана тела и расстановки суставов: ориентатор чисто геометрический, категория назначается подсчётом очков по словам Vision, а индекс скелетов читается только для подсказки «похожие риги» агенту сессии.

Шесть хранилищ

1. Индекс скелетов mt/skeleton_db.py · skeleton_db/skeletons.json · 3,06 МБ · 413 записей

Назначение
Ближайшие ранее риганные задачи, чтобы агент сессии мог предложить «повторить тот конвейер».
Ключ
id запуска (run).
Что хранит
Текстовые поля (описание, категория, план тела, кости, клипы, статус QA, операции) и четыре вектора: topology 128 (хэш имён костей, рёбер parent→child, глубины), pose 128 (длины и направления 24 костей, нормированные на высоту; не абсолютные позиции), anim 128 (хэш имён клипов), text 512 (CLIP-эмбеддинг описания). Категория — обычное поле, в векторы не входит.
Кто пишет
Конвейер после QA фоном; --index-all. Состав: humanoid 298, quadruped 71, other 18, hands 12, vehicle 4, bird 3.
Кто читает
fast_analysis кладёт 3 соседа по topology в fast.json["similar"] и в дайджест агента; API /api/mt/skeletons/similar; кэш анализа переиспользует вектора как дескриптор.
Поиск
Полный перебор по косинусу одного вида вектора.
Не используется
rig_first / fastrig (расстановка суставов), назначение категории, ось «верх» и «перед».
Слабость
Все риги одного шаблона дают cos 1,0 по топологии: у свежего запуска соседи — кабан, «робот-краб» и «other».

2. Кэш анализа mt/analysis_db.py · analysis_db/analysis.json · 2,28 МБ · 352 записи

Назначение
Пропустить или сократить вызовы Vision на ферме в фазе analysis.
Ключи
Уровень 0: sha256 исходника (или без helper-мешей). Уровень A: дескриптор рига {topo, pose} из индекса скелетов. Уровень B: CLIP-эмбеддинг (512) листа проекций sheet_lit.png.
Что хранит
run, sha, forward_axis, ответ классификации (what / body / rest_pose / materials / hair / props), план тела, категория, geo, img, счётчики hits / disputed.
Поиск
Точное совпадение по sha; гео-совпадение (topo cos ≥ 0,98 и pose cos ≥ 0,90) — выключено по умолчанию после того, как ёжик был прочитан как краб; совпадение по картинке требует CLIP cos ≥ 0,97 и согласия гео. Попадание превращается в синтетический ответ Vision, настоящий Vision потом подтверждает фоном (ждём до 40 с; расхождение → перериг).
Статистика
Попаданий 37 из 255 (~15 %): exact 23, geo 8, img 6; подтверждений 8 согласных, 4 спорных. Состав: humanoid 256, quadruped 61, other 14.
Не используется
Ось «верх»/«перед» от похожей модели не берётся: своя ось рига остаётся, выравнивание всегда идёт в настоящий Vision.

3. CLIP ViT-B/32 на numpy mt/clip_np.py · models/clip-vit-b32.npz · 304 МБ

Что это
Обе башни CLIP в numpy: embed_images и embed_texts дают единичные векторы 512.
Кто вызывает
Индекс скелетов (текст описания), кэш анализа (лист проекций), библиотека текстур texlib (альбедо и тексты, порог переиспользования 0,60; 806 наборов, texlib/embeddings.npz 4,3 МБ), разовый скрипт поиска по галерее.
Банки
Размеченного банка и центроидов по категориям нет: только поиск ближайшего соседа среди 352 листов и 806 текстур.
Исследование, не прод
orient_parts.py (CLIP-пробы «upright» / «front») и контракт orient-by-parts с хранилищем orient_parts_lib.npz, которого на проде нет.

4. Приоры категорий: правила и списки слов fast_registry.json v11 · creature.py · monster.py · multilimb.py · constitution.py

Реестр категорий
13 категорий (humanoid, quadruped, hands, vehicle, bird, multi_legged, fish, upright, serpent, insect…): слова тела, regex ключевых слов и подкатегорий, обязательные кости, диапазоны пропорций (нога/рост, рука/рост, голова/рост), список проверок, правила для агента.
Как назначается категория
Очки: совпадение body от Vision — 5, regex по what/hair/props — 2, план «hands» — 10; неизвестное тело создаёт новую категорию по ближайшей базовой. Эмбеддинги не участвуют. Результат в analysis/category.json.
Планы существ
creature.plan_for: слова → bird / upright / serpent / multileg / quadruped / biped; списки BIRD_WORDS, FISH_WORDS, UPRIGHT_WORDS, PRIMATE_WORDS, QUAD_WORDS и др. Монстр: слова + геометрические пороги (короткие ноги < 30 % H, длинные > 56 %). Многорукие: слова + минимальная длина лишней руки + вопрос Vision по видам.
Конституция
Диапазоны пропорций по подкатегориям; к ригу применяются только ultra_fat и toy_mascot (уверенность ≥ 0,6).
Библиотека движений по видам
animal_motion_lib/<вид>/<клип>.json (horse, zebra, cat, fox, boar, buck, creature…); родство VIDEO_KIN делит клипы (zebra → horse → donkey).

5. Бэкенд сайта autorig-online/backend

Категория
Только читает category.json / fast.json (заголовки SEO, загрузки). Реестр живёт в MT.
Эмбеддинги
Ни картинок, ни мешей для похожести в галерее или дедупа нет. Единственный семантический поиск — внешний прокси free3d.online. Лиц-эмбеддингов нет, сходство аватара — суждение Vision.
Наследие
Rig-v2: Vision возвращает animal_type из 12 поддерживаемых видов.

6. Нормы стенда mt/stand_analysis.py · stand/analysis.json

Что это
p10 / медиана / p90 метрик стенда (шаг, локти, колени) по категориям, по задачам без дефектов; пороги детекторов в DETECT.
Использование
Только отчёт; никто их не запрашивает в конвейере.

Вывод

Того, что вы ожидаете («воксельный анализатор понимает, где ноги и руки, и сверяет их топологию с базой категории»), в проде нет. Есть 413 скелетов с векторами длин и направлений костей, но они не сравниваются с текущей моделью ни при выборе «верха», ни при фите. Ось «верх» решают геометрия (orient.estimate_up, base_guard) и воксельный судья лежащего бипеда, план тела — слова Vision и списки слов.

Что сделать, чтобы база работала на риг

  • Собрать из индекса скелетов приор категории: по 413 записям (только с пройденным QA) — канонические пропорции и направления цепочек ног/рук/шеи относительно «верха» для каждой категории реестра. Это один файл skeleton_db/category_priors.json, версионируемый.
  • Использовать приор в выборе «верха» и плана тела: кандидат оси отклоняется, если трассированные цепочки ног смотрят вбок или вверх, а голова вниз относительно приора. Агент «Orientation · V3» сейчас делает первую версию на задаче cb402cd3.
  • Заменить topology-вектор, который даёт cos 1,0 для всех ригов одного шаблона, на вектор, в котором есть пропорции и пространственная раскладка (он уже есть как pose; искать по паре topo+pose).
  • Включить гео-уровень кэша анализа обратно только вместе с приором, который отбрасывает «ёжик = краб».
