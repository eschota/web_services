Rig Architecture

A transparent map of what happens between "upload" and a production-ready rigged character: every stage, every quality gate, and everything the rig contains when it lands in your downloads.

The Pipeline

Every task moves through the same guarded route: created → processing → done. Each box below is a real stage of the system, not marketing — this is how the service is actually wired.

Entry A

Upload a model

GLB, FBX or OBJ — direct upload or a link. ASCII FBX is rejected; binary FBX is pre-converted to GLB on the farm before rigging.

Entry B

Generate from an image

An AI vision check decides if the picture is riggable, then Flux renders a clean pose and Hunyuan3D builds the mesh. The result is auto-submitted to the same rigging pipeline.

↓
Queue

Task created

The task enters the queue. The scheduler only hands work to free GPU workers, so a busy farm means waiting in created — never a silent failure.

↓
Gate 1

Source preflight

The first bytes of the source are checked against real binary signatures (glTF, binary FBX, OBJ). An HTML page, an empty response or a corrupt file is rejected before a GPU minute is spent.

↓
Metadata

AI model description

A vision model writes the title, category and keywords for the model. This metadata travels with the task and drives animation selection and gallery listing.

↓
Dispatch

GPU converter farm

The task is sent to a GPU rigging worker. If a worker misbehaves, it is quarantined for 15 minutes and the task silently re-queues — no user-visible error for transient farm hiccups.

↓the pipeline splits by character type
🧍 Humanoid branch

Pose detection

Up to 137 OpenPose markers: 25 body, 21 per hand, 70 face. Orientation, scale and T-pose are normalized; fingers are detected individually.

↓

Skeleton + auto skinning

An AI-placed skeleton (spine, limbs, head, fingers) with automatic weight painting, plus a full Blender control rig for manual animation.

↓

64 animation clips

Retargeted onto the new skeleton: 12 walks, 12 fight moves, 10 emotes, 8 runs, 6 idles, 5 dances, 4 jumps, 3 deaths and more.

🐾 Animal branch

Species detection

AI vision classifies the animal into one of 12 supported species and must be confident before rigging starts — no guessing on ambiguous creatures.

↓

Geometry analysis + rig

The mesh goes through staged geometry analysis (limb tips, body segments, forward-axis semantics) before an animal control rig is built and bound.

↓

30 canonical clips × 24 variants

A versioned animation library: 30 clips (idles, gaits, turns, jumps, attacks, death, eat, sleep…) fitted to 12 species in 2 orientations.

↓
Gate 2

Completion contract

A task only counts as done when the worker reports it finalized with zero errors, and the preview video, poster and downloadable archive all actually exist.

↓
Publish

Viewer + durable cache

Viewer files (prepared.glb, animations.glb) are validated byte-for-byte before publishing. All deliverables are mirrored into a durable cache on the web host, so downloads survive farm cleanups, and are streamed with HTTP range support.

Watchdog, the whole way through: a task with no progress for 30 minutes is pulled back and re-queued automatically (up to 3 restarts); a hard 2-hour limit guarantees nothing hangs forever. Failed members of batch collections retry themselves without any manual action.

What's Inside the Rig

Two rig families, one delivery standard.

🧍 Humanoid rig

  • Skeleton derived from up to 137 OpenPose markers (25 body + 42 hand + 70 face)
  • Automatic skin weights on the full body and fingers
  • Blender control rig (.blend) for hand-keyed animation
  • 64 baked animation clips ready for game engines
  • Unity HDRP .unitypackage with the character set up
  • All-animations FBX + skeleton.json
  • Prepared GLB for the built-in web viewer

🐾 Animal rig

  • 12 species: dog, bear, cat, cow, deer, elephant, giraffe, horse, mouse, pig, rabbit, turtle
  • 2 orientations per species → 24 rig variants per task
  • 30 canonical clips: 5 idles, walk/trot/run/sprint, turns, jumps, attacks, hits, death, eat, sleep, vocalize
  • Versioned animation library — clips are pinned to your task's revision and verified by checksum
  • Per variant: .blend, .fbx, skeleton.json and a viewer animations.glb
  • Rig blueprint: skeleton JSON + rig preview video

Inside the Skeleton

Every rig is built as two layers: a control rig for animators and a deform skeleton that actually moves the mesh in engines.

🎛 Control layer

  • Full IK/FK control rig (Auto-Rig Pro architecture): root and trajectory masters, IK chains with pole targets, FK switches per limb
  • Shipped in the .blend files — this is what you animate by hand in Blender
  • Quadruped rigs carry 300+ nodes end-to-end; humanoids are built from the OpenPose marker set (25 body + 42 hand + 70 face)

🦴 Deform layer

  • The bones that carry skin weights and drive the mesh in Unity, Unreal and the web viewer
  • Exported inside every GLB/FBX with the skinned mesh and baked clips
  • Published per task as skeleton.json — the exact joint hierarchy contract, machine-readable

📐 Contracts

  • Viewer GLBs must contain a valid skin and a mesh bound to it — a rig without skinning fails the contract and the task fails loudly
  • Animal tasks additionally publish a rig blueprint: blueprint/skeleton.json + a rig preview video
  • Animation manifests carry sha256, clip count and revision headers, so a viewer can verify what it plays

Animal Rig, In Depth

Non-humanoid rigging is its own pipeline: geometry understanding first, skeleton second, and a canonical animation taxonomy on top.

Stage 0

Species detection

AI vision classifies the model into one of 12 supported species and must clear a confidence threshold before rigging starts. Unsupported body topologies are rejected at task creation.

Stage 1

Geometry field (MCF)

The mesh is analyzed as a single closed body; disconnected shells and non-manifold glue are detected here, before any bones exist.

Stage 2.1

Pre-semantics

Terminal tips are extracted — a quadruped needs all four leg tips found on the mesh, plus tail and head candidates.

Stage 2.2

Body semantics

The forward axis is chosen and every limb gets a role (front-left leg, tail, neck…), cross-checked by independent sanity rules.

Stage 3

Rig & bind

An Auto-Rig Pro quadruped control rig is generated on the semantic markers and the mesh is bound with automatic weights.

Stage 4

Clips & variants

Animation clips are retargeted onto the new skeleton and the task publishes its variant files: .blend, .fbx, skeleton.json and a viewer animations GLB.

The Canonical Animation Taxonomy

All animal animation work targets one canonical 30-clip set — enough to build a complete animation controller for an RPG-style creature without custom work. Clips snap together through four shared junction poses (default, locomotion contact, airborne, death end), so any clip can transition into any compatible neighbour.

CategoryClipsFrames @30fpsLoop
Idle ×5 neutral, alert, relaxed, look around, fidget 97 yes
Locomotion ×9 walk, walk backward, trot, run (gallop), sprint, turn left 90°, turn right 90°, turn 180°, stop/brake 49 / 33 gaits loop
Air ×5 jump start, air loop, jump land, full jump, fall 33–49 air loop only
Combat ×8 attack primary / secondary / heavy, hit front / left / right, death, get up 33–65 no
Behavior ×3 eat, sleep/rest, vocalize (roar / bark / neigh) 97 / 33 eat & sleep loop

Every species ships in two orientations (front / back) — 12 species × 2 orientations = 24 rig variants per task, with the detected species as the primary. Animation libraries are versioned: each artifact carries a sha256-verified manifest, and a task is permanently pinned to the library revision that was active when it was created — a later library update never silently changes an existing rig.

Quality Gates

Every stage that can produce a bad rig has a gate in front of it. If a gate fails, the task fails loudly — a broken rig is never silently delivered.

Binary signature preflight

Sources are verified against real file magic before queueing; web pages and corrupt files never reach the farm.

Riggability vision check

Generated characters are screened for pose and separated limbs before any credits are spent on rigging.

Topology check at creation

Unsupported animal body topologies are rejected at task creation with a clear error, not mid-pipeline.

Worker completion contract

Workers must explicitly report a finalized, error-free result — partial output can't masquerade as success.

Deliverables completeness

Preview video, poster and the downloadable archive are verified to exist before a task is marked done.

Strict viewer validation

Viewer GLBs are checked for a valid binary glTF header and exact declared size before they are published.

Checksummed animation library

Animal clips ship from a versioned library with sha256-verified manifests and a visual phase QA pass.

Watchdog + auto-restarts

Stalled tasks are re-queued automatically up to 3 times; a global timeout guarantees a definite outcome.
